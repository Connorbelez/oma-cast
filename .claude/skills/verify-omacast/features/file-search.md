# File search

omacast keeps a list of the user's files in memory, built with `rg --files` over the home dir and `~/.config` (with hidden files). A daily full count finds large untouched subtrees, directories over 5,000 files with no zoxide entry or active git repo inside, and leaves their files out of the list. P7-1 ships the list, the detection, the ignore file, the `files.*` RPCs and the doctor lines. P7-2 ranks the names and adds the Search Files view. P7-3 adds the preview pane, Quick Look and the file actions. P7-4 adds a Files section to root search. P7-5 adds a Contents section and a Names / Contents dropdown to the Search Files view.

## Sub-features

- `files-list` the in-memory list. It is built when the plugin loads, after the first recount, in 65 to 152 ms on the dev machine with the cache present (four reloads). It is refreshed 250 ms after the launcher hides once it is older than 30 s, and 250 ms after an open only once it is older than 10 minutes; an open cancels a pending hide refresh. It is never refreshed while a refresh is running; a refresh requested during one runs right after it. Each listing logs `[omacast] [info] files: listed <n> paths in <ms> ms` and is followed by the signal probe, zoxide plus `fd` over the home dir to depth 8, about 70 ms outside the shell. A run that exits 1 with no output (a root with no files) counts as an empty root. A run that exits 2 with output, which is how rg reports a directory it could not read, is accepted and logs `files: rg exited 2 for <root>; listed what it could read`, so a root-owned directory under the home dir does not leave the user without a list. The previous list stays when either run is killed, exits with any other code, or exits 2 with no output (`files: rg exited <code> for <root>; keeping the previous list`, with `abnormally` for a signal). Each run is limited to 15 s by coreutils `timeout`. On a timeout the log has `files: refresh timed out`, the whole process group is killed, and the previous list stays.
- `files-ignore-file` `~/.config/omacast/file-search.ignore`, created with the build dirs and the private paths on first start, mode 0600. Patterns with a slash are relative to the home dir. rg lists everything when an ignore file is missing, so no listing runs without both files. A refresh that finds one missing or unreadable logs `files: an ignore file is missing; recreating it`, recreates it, and lists again. If it is still unreadable, it logs `files: ignore file missing, keeping the previous list`. A line rg cannot parse is logged once (`files: rg cannot read the ignore line …`) and matches nothing.
- `files-large-subtrees` the daily recount, one `rg --files ~ | awk` process outside the shell (`files: counted <n> paths, <k> large untouched subtrees in <ms> ms`, 616 to 745 ms on the dev machine). It runs at load when the cached result in `~/.cache/omacast/file-search.json` is a day old or missing, and on hide when one is due, after that refresh lands. One unreadable directory makes it exit 2; it still counts (`files: recount exited 2 for <home>; counted what it could read`). It is limited to 60 s (`files: recount timed out`, the process group is killed and the previous subtrees stay). After a failure or a timeout the next recount waits an hour, and a fresh install has no list until one succeeds. Detected trees go into `~/.cache/omacast/file-search-untouched.ignore`, so the list leaves them out whether or not the user accepts the toast. That file is also recreated from the last recount when it goes missing.
- `files-toast` `files.takeToast` returns "Skipping ~/Applications/UnrealEngine (300,136 files)" once per tree (the footer shows about 52 characters, so the title carries no question; the Ctrl+T action does), records `fileSearch.askedAt[path]` in `db/settings.json`, and offers it again after 7 days. `prepare()` in `ui/LauncherWindow.qml` calls it on every open and shows the result in the footer for 6 s. Ctrl+T opens the toast's action "Add to Ignore File", which calls `files.ignore`.
- `files-rpc` `files.list` (count, roots, timing, paths in pages of at most 1,000, optional `under`), `files.refresh` (optional `roots`), `files.largeSubtrees`, `files.ignore` (append one path under the home dir).
- `files-doctor` `omacast doctor` prints the count, both roots, the ignore file and each large subtree.
- `files-rank` `core/FileRanker.js` puts each name in a band: 0 exact name or stem, 1 prefix, 2 word start (after `-`, `_`, `.` or a space), 3 substring, 4 subsequence, 6 path only (every word but the last starts a path segment and the last matches the name in bands 0 to 2). A multi-word query whose words all start words in the name is band 2. Within a band, rows sort by `ln(1 + opens / 100) + 0.5 × recency + 0.5 × prior`, then by shorter name. Opens are omacast's frecency for the absolute path; recency is 0 because `rg --files` gives no mtime; the prior is `ln(1 + zoxide score)` of the nearest weighted folder, plus 2 for a repo whose `HEAD` reflog changed in 14 days, plus `ln(1 + opens / 100)` per opened file below it, over `1 + 0.5 × distance`. A file with frecency 50 or more moves from band 3 to 6 up one band; bands 0 to 2 never move. One open scores 101 and halves every 10 days, so it lifts the file for 10 days. Each search logs `[omacast] [info] files: ranked <hits> of <n> in <ms> ms`.
- `files-view` `builtin:search-files` ("Search Files", subtitle "File Search") pushes the `files` view: placeholder "Search files…", footer title "Search Files", at most 50 rows, each the file name with its folder (`~` for the home dir) as the subtitle. The empty query shows "Recent & frequent files", ranked by usage alone, the files opened from omacast first; a query shows "Files". The view answers synchronously in `rootSearch.search`, so no reply is ever late and nothing logs `dropped` here. When a new list or signal probe lands while the view is open, the view rebuilds 50 ms later without a keystroke, so a `files: ranked` line follows `files: listed`; after a plugin reload the recent list fills in once the first list lands. Esc, Ctrl+[, Backspace on an empty query and Shift+Esc leave it like any pushed view.
- `files-open` ↵ (or a click, or Ctrl+1–9) on a file row opens it through the same code as `files.open`. It records a frecency visit keyed by the absolute path (no search term, no search history), runs `uwsm-app -- xdg-open <path>`, hides the launcher and shows the file name in Omarchy's OSD.
- `files-search-rpc` `files.search '{"query":…,"limit":…}'` returns `{ hits, count, ms, rows: [{ id, path, title, subtitle, band, score }] }`, at most 50 rows. `files.open '{"path":…}'` takes the absolute path of a file in the current list and answers the error `not in the file list` for any other path, without opening or recording it.
- `files-preview` the right-hand pane of the `files` view (`ui/FilePreview.qml`). The list keeps 42% of the width whenever the view is open, so rows never move. The pane shows the row's name and folder at once and loads the rest after the selection has been still for 80 ms; a selection change cancels a pending load and a load that lands for another row is dropped. One fixed script (`FileActions.previewScript`) stats the file and reads what the pane needs: the first 64 KB of a text file (`head -c 65536`), shown as its first 200 lines in the monospace font; `file -Lb` for a raster image's pixel size (the last W×H not labelled `density` or `resolution`, or TIFF's `width=` and `height=`), with the image decoded by Qt at its own size, or scaled down to fit 1,600 by 1,600 px when a side is larger, never scaled up; the first 4 KB of an SVG for its `width`/`height` or `viewBox`; `pdftotext -l 1` for a PDF's first page when `pdftotext` is on PATH. Text and PDFs over 1 MB, images over 20 MB, binary extensions, content holding a NUL byte, unreadable files, FIFOs and other non-regular files show metadata only ("No preview"), still with Size and Modified. The script runs under `timeout -k 2 10`. A load that takes longer shows the metadata and logs `files: preview timed out`, and a selection change sends SIGTERM to `timeout`, which ends the script and any `pdftotext` under it. Below the content the pane lists Name, Where, Kind, Size, Modified and, when known, Dimensions or Lines. Each load logs `[omacast] [info] files: preview <kind> <ms> ms, <ms> ms after the selection` when the pane gets its result, or for an image when Qt has decoded it: the first number is the load, the second includes the 80 ms still-time.
- `files-actions` Ctrl+K on a file row lists Open (↵), Show in Folder (Ctrl ↵), Open With… (Ctrl Shift ↵), Quick Look (Ctrl Y), Copy Path (Ctrl Shift C) and Move to Trash (Ctrl D). Show in Folder runs `uwsm-app -- xdg-open <folder>` and hides the launcher. Open With… opens a picker of the installed apps sorted by name ("Open <name> with…"); ↵ on an app acts on the file the picker opened for: it records a frecency visit for the file, runs `uwsm-app -- gtk-launch <id>.desktop <path>`, hides the launcher and shows the file name in the OSD. While the picker is open the pointer does not select rows and a paste goes to its filter. Esc closes the picker. Copy Path sends the absolute path to `wl-copy` on stdin, hides the launcher and shows "Copied to Clipboard" in the OSD. Move to Trash asks first ("Move to Trash", "Move <name> to the Trash?"); ↵ runs `gio trash -- <path>`, Esc cancels. On success the row leaves the list at once, the file's frecency record is deleted, the list refreshes on the next hide, the footer says "Moved <name> to the Trash" and the log has `files: moved a file to the Trash`. A failure says "Could not move <name> to the Trash" and logs `files: gio trash failed`. While `gio` runs, and after it moves the file until a listing has it again, every action on that row does nothing, so a second ↵ at the alert opens nothing. Only a file under the home dir goes to the Trash. `files.refresh` rejects a root with a `.` or `..` segment or `//`, so every listed path is normalised and the home-dir check cannot be walked out of.
- `files-quick-look` Ctrl+Y (or the Quick Look action) widens the pane over the list. Arrow keys still move the selection underneath. Esc or Ctrl+Y closes it with the same row selected. With the action, toast or about panel open over it, Esc closes the panel first and a second Esc closes Quick Look. It closes when the launcher hides or the view has no file selected.
- `files-actions-rpc` `files.preview '{"path":…}'` returns the last preview loaded for that path (what the pane shows), or starts a load and returns `{ path, pending: true }`; call it again for the result `{ kind: "text"|"image"|"pdf"|"meta", path, name, dir, size, mtime, text?, lines?, truncated?, imageSource?, width?, height? }`. `files.showInFolder`, `files.copyPath` and `files.trash` take `{ path }`; `files.trash` skips the alert and returns `{ started: true }`. `files.openWith '{"path":…}'` lists `{ apps: [{ id, name }] }`, and with `"app"` it launches. Each answers `not in the file list` for a path outside the current list, and `files.trash` answers `Only files under <home> go to the Trash` for a listed path outside the home dir.
- `files-root` typing at the root shows a Files section after Results and before `Use "<q>" with…`, at most 3 rows with the same shape as the files view's rows. It shows for a query of 3 or more characters with a name-band hit (bands 0 to 4 or 6), and never for the empty root, 1 or 2 characters, a query that equals an enabled command's alias, or the Applications and Commands filters. A query that starts with `~/` or `/` is a path: it lists the files under that path, ignoring case, by the usage score and then the shorter path, and shows the Files section alone. When nothing is listed under the path, the root shows its usual sections. `rootSearch.search` ranks the files in the same task as the rest of the reply, so the launcher's serial guard drops a late section along with its Results. Each name query logs `files: ranked`; each path query logs `files: matched <n> paths of <total> in <ms> ms`. ↵, a click or Ctrl+1–9 opens the file as `files-open` does. Ctrl+K on a root file row lists Open, Show in Folder, Open With… and Copy Path; Quick Look and Move to Trash stay in the Search Files view. With `"logLevel": "debug"` in `~/.config/omacast/config.json`, every applied search logs `[search] rows in <ms> ms`, the time from the keystroke's rebuild to the rows on screen.

- `files-contents` the Search Files view's Contents section. 150 ms after the last keystroke the view asks `Backend.searchContents`, which applies the reveal rule: a trimmed query of 3 or more characters with a space in it or fewer than 5 listed names that hold the whole query, ignoring case. `ContentSearch` then runs one fixed script under `timeout -k 2 5` from the home dir, with the query on stdin: `rg --json -F -i -f - --max-count 1 --max-filesize 1M -j 32 --ignore-file <ignore file> --ignore-file <untouched file> <home>` and, at the same time, the same with `--hidden` over `~/.config`, joined by `cat` so their lines never interleave, passing on only `match` lines of at most 4,096 characters for at most 1,000 files. The rows are listed files only, best folder prior first, then the shorter path, at most 20, under a "Contents" header below the name rows. The section replaces the Files section's loose rows, the unlifted subsequence-only matches (band 4); exact, prefix, word-start, substring, path and lifted rows stay above it. Each row's title is the file name and its subtitle the matching line, trimmed, starting at the matching word when the match is more than 16 characters in, or the folder when rg prints the line only as bytes. The preview pane's Where shows the folder. ↵ and every file action work as on a name row. The log has `content: <n> files in <ms> ms` (match lines read, before the listing filter and the cap), `content: cancelled` when a keystroke, a view change, a hide or a new request stops a run, `content: killed at 300 ms` from the kill timer (the rows read before it still show), `content: dropped a reply for an older query` when the view drops a late reply, `content: an ignore file is missing, so nothing was searched` when the script exits 3, and `content: rg did not exit; giving up on it` from the 3 s watchdog. While the view has no rows and a content search is due or running, it says "Searching Contents…". With `"logLevel": "debug"`, each Contents section logs `[search] contents painted <ms> ms after the keystroke` at the first frame that shows it.
- `files-contents-dropdown` Ctrl+P in Search Files opens a Names / Contents dropdown, and the header button shows the current choice. Contents hides the name rows and searches contents for every query of 3 or more characters; below that the view says "Search Contents" and "Type 3 or more characters to search inside files." The choice belongs to the pushed view, so leaving Search Files and coming back starts on Names.
- `files-contents-rpc` `files.searchContents '{"query":…,"forced":…}'` answers `{ query, revealed: false }` when the reveal rule says no, and otherwise starts a search and answers `{ query, pending: true }`. The next call with the same query answers `{ query, serial, rows, ms, killed }` once the reply has landed, and the call after that starts a new search. It shares `ContentSearch` with the view, so a call cancels the view's running search.

## How to get to it (user POV)

- Run `omacast doctor`.
- Run `omacast call files.list '{"limit":0}'`, `omacast call files.largeSubtrees '{}'`.
- The toast in the launcher footer on the first open after a tree is detected, and Ctrl+T then ↵ to accept it.
- Type `search files` in the root and press ↵, or run `omacast run builtin:search-files`.
- Type 3 or more characters of a file name, or a path such as `~/Pro`, at the root.
- Run `omacast call files.search '{"query":"oma spec"}'`.
- In Search Files, type 3 or more characters that few file names hold, such as `frec`, and wait. Ctrl+P switches between Names and Contents.
- Run `omacast call files.searchContents '{"query":"frec"}'` twice.

## Driving it with omacast-verify

Preconditions:

- The baseline from the README holds.
- Save `~/.config/omacast/file-search.ignore` and `jq .fileSearch ~/.local/share/omacast/db/settings.json` first, to restore them at the end.

- **List.** Run `$V open`, then `$V call files.list '{"limit":0}' | jq .data.count` within 100 ms. The count is about 20,000 on the dev machine (14,956 from the home dir and 4,939 from `~/.config`).
- **Refresh on hide.** `$V open`, wait 31 s, `$V hide`, wait 1 s, `$V open`. `$V log 120` has one `files: listed` line after the hide and none after the second open. Ten rounds of open, 31 s, hide took 22 to 62 ms on the dev machine, median 40. Rounds alternate between about 22 and 57 ms, which matches a JS garbage collection landing in every other parse.
- **Hidden config root.** `$V call files.list '{"under":"'$HOME'/.config/hypr","limit":1000}'` holds `~/.config/hypr/hyprland.lua`. Page through `files.list` with `offset` and check that no path sits under `~/.config/chromium`, `~/.config/zen`, `~/.ssh` or a `Cache/` dir.
- **Large subtrees.** `$V call files.largeSubtrees '{}'` lists `~/Applications/UnrealEngine` (300,136) and `~/node_modules` (12,558, `ignored: true` because the default ignore file has `node_modules/`), and not `~/Dev`.
- **Failure keeps the list.** `$V call files.refresh '{"roots":["/nonexistent"]}'`, wait 1 s, then `files.list`. The count and roots are unchanged, and the log has one `files: rg exited 2 for /nonexistent; keeping the previous list`.
- **Missing ignore file.** Copy `~/.config/omacast/file-search.ignore` aside, delete it, `$V call files.refresh '{}'`, wait 2 s. The count is unchanged, `files.list '{"under":"'$HOME'/.config/chromium","limit":0}'` has `matched: 0`, the file is back at mode 0600 with the defaults, and the log has `files: an ignore file is missing; recreating it`. The same holds for `~/.cache/omacast/file-search-untouched.ignore`.
- **Hung rg.** `mkdir ~/omacast-hang && mkfifo ~/omacast-hang/.ignore`, then `$V call files.refresh '{}'`. rg blocks opening the FIFO, `files.list` reports `refreshing: true`, and after 15 s the log has `files: refresh timed out` and `refreshing` is false. `ps -eo pid,ppid,args | grep -E '[r]g |[a]wk |[f]d '` then shows no omacast rg, and once the signal probe's own 15 s pass, no fd either. Free and remove it with `bash -c 'exec 3<>"$1"; : >"$1.new"; mv -f -- "$1.new" "$1"; exec 3>&-' _ ~/omacast-hang/.ignore; rm -rf ~/omacast-hang` right away, because every rg and fd that walks the home dir blocks on it.
- **Toast and accept.** `$V call files.takeToast '{}'` returns the toast with a `files.ignore` action, and a second call returns `null`. `$V call files.ignore '{"path":"'$HOME'/Applications/UnrealEngine"}'` appends `/Applications/UnrealEngine/` to the ignore file, which stays 0600, and a second call returns `added: false`.
- **Argv.** A refresh lasts about 25 ms, too short to catch with `ps`; hold it with the FIFO above (one under `~` and one under `~/.config`). `ps -eo args | grep '[r]g '` then shows only `rg --files [--hidden] --ignore-file ~/.config/omacast/file-search.ignore --ignore-file ~/.cache/omacast/file-search-untouched.ignore <root>` and its parent `timeout -k 2 15 bash -c <constant list script> omacast-files <root> <the two ignore files> [--hidden]`. During a recount it shows `timeout -k 2 60 bash -c <constant script>`, `rg --files <home>`, `awk -F/ -v threshold=5000 <constant program>` and `fd … --exclude node_modules <home>` under `timeout -k 2 15`.
- **Doctor.** `bin/omacast doctor` prints `file search lists … files from <home> and <home>/.config`, the ignore file, and one `left out, large and untouched` line per tree.
- **Push the view.** `$V open`, `$V key ctrl+u`, `$V type "search files"`, `$V key enter`, `$V shot files-empty`. The placeholder reads "Search files…" and "Recent & frequent files" heads the rows. For 1.3 to 2.3 s after every open the footer shows "Loading…", because `backend.loading` includes `menuSource.loading` and the Omarchy menu probe runs on each open (this predates Phase 7). After that, and once any toast has gone, it shows "Search Files".
- **Path band.** `$V type "oma spec"`, `$V shot files-oma-spec`. The first row is `SPEC.md` with `~/Projects/oma-cast`; on the dev machine a second `SPEC.md` under `~/.config/omarchy/plugins/omamail/docs` follows.
- **Keystroke time.** Type `s`, `p`, `e`, `c` one `$V type` at a time and read `qs log -n -p "$OMARCHY_PATH/shell" -t 40 | grep 'files: ranked'`. On the dev machine (19,919 to 19,923 files), outside a collection pause, `s` takes 4 to 7 ms, `sp`, `spe` and `spec` 2 to 4 ms, and multi-word queries such as `oma s` and `app tsx` 3 to 5. A one-character query that most names contain costs more, because the substring scan scores every matching row: headless at 14,964 files, `.` took 15 ms and `-` 9 ms. A pause of the shell's garbage collector adds 13 to 37 ms to the search it lands in. After `$V run builtin:search-files` that was 1 search in 120; after typing `search files` at the root, whose searches leave garbage behind, it was 10 in 105.
- **Open.** `$V key ctrl+u`, `$V type "claude"`, `$V key enter`, `$V shot files-open-hud` within 1.5 s. The OSD names `CLAUDE.md`, the layer is gone, and `$V call frecency.get '{"id":"'$HOME'/Projects/oma-cast/CLAUDE.md"}'` has a score of about 101 and no search terms.
- **Recent.** `$V open`, `$V run builtin:search-files`, `$V shot files-recent`. `CLAUDE.md` is the first row under "Recent & frequent files". `$V key shift+escape` returns to the root with an empty query.
- **Preview, text.** `$V open`, `$V key ctrl+u`, `$V run builtin:search-files`, `$V type "claude"`, wait 300 ms, `$V shot preview-text`. The pane shows the first lines of `CLAUDE.md` with Kind Text, about 19 KB and its line count. The log has `files: preview text 3 ms, 84 ms after the selection` or close to it (3 to 4 ms load, 83 to 91 ms from the selection over ten rows on the dev machine).
- **Preview, image.** `$V key ctrl+u`, `$V type "preview.png"`, `$V shot preview-image`. The pane shows `~/Projects/oma-cast/preview.png` and Dimensions `1712 × 1158`. Image loads took 12 to 61 ms (93 to 144 ms from the selection) over thirteen PNG screenshots, most of it Qt decoding the PNG.
- **Preview, JPEG.** `cp /usr/share/omarchy/themes/ethereal/backgrounds/1-cosmic.jpg ~/Projects/oma-cast/p1-density-check.jpg`, `$V call files.refresh '{}'`, wait 1.5 s, `$V key ctrl+u`, `$V type "p1-density-check"`. Dimensions read `5120 × 2880`, not the JFIF density `96 × 96`. Delete the copy.
- **Actions.** `$V key ctrl+k`, `$V shot actions`, `$V key escape`. Six entries with the shortcuts above.
- **Copy Path.** Select `SPEC.md` (`$V type "oma spec"`), `$V key ctrl+shift+c`. The launcher hides, the OSD says "Copied to Clipboard" and `wl-paste -n` prints `/home/<user>/Projects/oma-cast/SPEC.md`.

The file is gone, `~/.local/share/Trash/files/omacast-trash-test.txt` and its `.trashinfo` (`Path=/home/<user>/omacast-trash-test.txt`) exist, the view says "No results" and the footer "Moved omacast-trash-test.txt to the Trash". The lines are `bash -c <constant script> omacast-preview <path> <mode> <limit>` and `pdftotext -l 1 -q -- <path> -`, plus `wl-copy` with no arguments after a Copy Path. Results, then Files with `SPEC.md` under `~/Projects/oma-cast` and two more rows, then `Use "spec" with…`. `$V titles spec | grep '##'` prints the three headers in that order.

## Gotchas

- Show in Folder, Open With… and ↵ start real apps on the user's desktop. Close each window the run opened, and trash only files the run created.
- Copy Path replaces the user's clipboard. Run it only on paths that may be shown, and only for text this run put there.
- Open With… records a frecency visit like ↵ does, so delete it afterwards.

- ↵ on a file runs the user's default app for it through `xdg-open`. On the dev machine Markdown opens in Chromium, as a tab in an open window. Open only files the run may show, and leave the window for the user.
- The empty query's rows are computed once per list and signals, 50 ms after the launcher hides or a new list or probe lands. A `files.search` call with another `limit` replaces that cached result, so the view's next empty query recomputes it (about 8 ms).
- Opening a file changes the folder prior: every folder above it gains `ln(1 + opens / 100)`. Undo test opens, or later ranks drift.
- A Contents row is a file like any other, and ↵ opens it through `xdg-open`. Pick a query whose every content match is a file the run may open, and check with `rg -l -F -i` over the same roots first.
- `files.searchContents` shares `ContentSearch` with the view, so a call while the view is searching cancels the view's search.
- ↵ while the toast shows activates the selected row, not the toast. Accepting the toast is Ctrl+T then ↵, like every toast action in the launcher. The toast leaves the footer after 6 s and does not return for 7 days, because taking it records the ask.
- `files.takeToast` records the ask. Calling it from a test hides the toast from the next real open for 7 days, so restore `fileSearch.askedAt`.
- `qs ipc` drops replies over about 200 KB. `files.list` returns 100 paths by default and at most 1,000 per call.
- rg anchors `--ignore-file` patterns at its working directory. Every run starts in the home dir, and a hand-run check must too (`cd ~`).
- The first recount on a fresh install walks all of `$HOME` (327,662 files on the dev machine) in about 0.75 s, and the first list waits for it.
- A FIFO under the home dir blocks rg, fd and the recount until something opens it for writing or `timeout` ends them, so each hide's refresh waits 15 s on it. Remove the hung-rg test dir as soon as the timeout shows. A plugin reload while one blocks leaves the recount's rg and awk and the signal probe's fd behind, because the shell SIGKILLs `timeout`; freeing the FIFO as the Hung rg step does lets them finish.
