# File search

omacast keeps a list of the user's files in memory, built with `rg --files` over the home dir and `~/.config` (with hidden files). A daily full count finds large untouched subtrees, directories over 5,000 files with no zoxide entry or active git repo inside, and leaves their files out of the list. P7-1 ships the list, the detection, the ignore file, the `files.*` RPCs and the doctor lines. P7-2 ranks the names and adds the Search Files view. The preview pane, file actions, a root Files section and content results come in later PRs.

## Sub-features

- `files-list` the in-memory list. It is built when the plugin loads, after the first recount, in 65 to 152 ms on the dev machine with the cache present (four reloads). It is refreshed 250 ms after the launcher hides once it is older than 30 s, and 250 ms after an open only once it is older than 10 minutes; an open cancels a pending hide refresh. It is never refreshed while a refresh is running; a refresh requested during one runs right after it. Each listing logs `[omacast] [info] files: listed <n> paths in <ms> ms` and is followed by the signal probe, zoxide plus `fd` over the home dir to depth 8, about 70 ms outside the shell. A run that exits 1 with no output (a root with no files) counts as an empty root. A run that exits 2 with output, which is how rg reports a directory it could not read, is accepted and logs `files: rg exited 2 for <root>; listed what it could read`, so a root-owned directory under the home dir does not leave the user without a list. The previous list stays when either run is killed, exits with any other code, or exits 2 with no output (`files: rg exited <code> for <root>; keeping the previous list`, with `abnormally` for a signal). Each run is limited to 15 s by coreutils `timeout`. On a timeout the log has `files: refresh timed out`, the whole process group is killed, and the previous list stays.
- `files-ignore-file` `~/.config/omacast/file-search.ignore`, created with the build dirs and the private paths on first start, mode 0600. Patterns with a slash are relative to the home dir. rg lists everything when an ignore file is missing, so no listing runs without both files. A refresh that finds one missing or unreadable logs `files: an ignore file is missing; recreating it`, recreates it, and lists again. If it is still unreadable, it logs `files: ignore file missing, keeping the previous list`. A line rg cannot parse is logged once (`files: rg cannot read the ignore line …`) and matches nothing.
- `files-large-subtrees` the daily recount, one `rg --files ~ | awk` process outside the shell (`files: counted <n> paths, <k> large untouched subtrees in <ms> ms`, 616 to 745 ms on the dev machine). It runs at load when the cached result in `~/.cache/omacast/file-search.json` is a day old or missing, and on hide when one is due, after that refresh lands. One unreadable directory makes it exit 2; it still counts (`files: recount exited 2 for <home>; counted what it could read`). It is limited to 60 s (`files: recount timed out`, the process group is killed and the previous subtrees stay). After a failure or a timeout the next recount waits an hour, and a fresh install has no list until one succeeds. Detected trees go into `~/.cache/omacast/file-search-untouched.ignore`, so the list leaves them out whether or not the user accepts the toast. That file is also recreated from the last recount when it goes missing.
- `files-toast` `files.takeToast` returns "Skipping ~/Applications/UnrealEngine (300,136 files)" once per tree (the footer shows about 52 characters, so the title carries no question; the Ctrl+T action does), records `fileSearch.askedAt[path]` in `db/settings.json`, and offers it again after 7 days. `prepare()` in `ui/LauncherWindow.qml` calls it on every open and shows the result in the footer for 6 s. Ctrl+T opens the toast's action "Add to Ignore File", which calls `files.ignore`.
- `files-rpc` `files.list` (count, roots, timing, paths in pages of at most 1,000, optional `under`), `files.refresh` (optional `roots`), `files.largeSubtrees`, `files.ignore` (append one path under the home dir).
- `files-doctor` `omacast doctor` prints the count, both roots, the ignore file and each large subtree.
- `files-rank` `core/FileRanker.js` puts each name in a band: 0 exact name or stem, 1 prefix, 2 word start (after `-`, `_`, `.` or a space), 3 substring, 4 subsequence, 6 path only (every word but the last starts a path segment and the last matches the name in bands 0 to 2). A multi-word query whose words all start words in the name is band 2. Within a band, rows sort by `ln(1 + opens / 100) + 0.5 × recency + 0.5 × prior`, then by shorter name. Opens are omacast's frecency for the absolute path; recency is 0 because `rg --files` gives no mtime; the prior is the nearest folder's zoxide score, plus 2 for a repo whose `HEAD` reflog changed in 14 days, plus `ln(1 + opens / 100)` per opened file below it, over `1 + 0.5 × distance`. A file with frecency 100 or more (one open) moves from band 3 to 6 up one band; bands 0 to 2 never move. Each search logs `[omacast] [info] files: ranked <hits> of <n> in <ms> ms`.
- `files-view` `builtin:search-files` ("Search Files", subtitle "File Search") pushes the `files` view: placeholder "Search files…", footer title "Search Files", at most 50 rows, each the file name with its folder (`~` for the home dir) as the subtitle. The empty query shows "Recent & frequent files", ranked by usage alone; a query shows "Files". The view answers synchronously in `rootSearch.search`, so no reply is ever late and nothing logs `dropped` here. Esc, Ctrl+[, Backspace on an empty query and Shift+Esc leave it like any pushed view.
- `files-open` ↵ (or a click, or Ctrl+1–9) on a file row opens it through the same code as `files.open`. It records a frecency visit keyed by the absolute path (no search term, no search history), runs `uwsm-app -- xdg-open <path>`, hides the launcher and shows the file name in Omarchy's OSD. The action panel offers only Open.
- `files-search-rpc` `files.search '{"query":…,"limit":…}'` returns `{ hits, count, ms, rows: [{ id, path, title, subtitle, band, score }] }`, at most 50 rows. `files.open '{"path":…}'` takes an absolute path.

## How to get to it (user POV)

- Run `omacast doctor`.
- Run `omacast call files.list '{"limit":0}'`, `omacast call files.largeSubtrees '{}'`.
- The toast in the launcher footer on the first open after a tree is detected, and Ctrl+T then ↵ to accept it.
- Type `search files` in the root and press ↵, or run `omacast run builtin:search-files`.
- Run `omacast call files.search '{"query":"oma spec"}'`.

## Driving it with omacast-verify

Preconditions:

- The baseline from the README holds.
- Save `~/.config/omacast/file-search.ignore` and `jq .fileSearch ~/.local/share/omacast/db/settings.json` first, to restore them at the end.

- **List.** Run `$V open`, then `$V call files.list '{"limit":0}' | jq .data.count` within 100 ms. The count is about 20,000 on the dev machine (14,956 from the home dir and 4,939 from `~/.config`).
- **Refresh on hide.** `$V open`, wait 31 s, `$V hide`, wait 1 s, `$V open`. `$V log 120` has one `files: listed` line after the hide and none after the second open. Ten rounds of open, 31 s, hide took 22 to 62 ms on the dev machine, median 40. Rounds alternate between about 22 and 57 ms, which matches a JS garbage collection landing in every other parse.
- **Hidden config root.** `$V call files.list '{"under":"'$HOME'/.config/hypr","limit":1000}'` holds `~/.config/hypr/hyprland.lua`. Page through `files.list` with `offset` and check that no path sits under `~/.config/chromium`, `~/.config/zen`, `~/.ssh` or a `Cache/` dir.
- **Large subtrees.** `$V call files.largeSubtrees '{}'` lists `~/Applications/UnrealEngine` (300,136) and `~/node_modules` (12,558, `ignored: true` because the default ignore file has `node_modules/`), and not `~/Dev`.
- **Failure keeps the list.** `$V call files.refresh '{"roots":["/nonexistent"]}'`, wait 1 s, then `files.list`. The count and roots are unchanged, and the log has one `files: rg exited 2 for /nonexistent; keeping the previous list`.
- **Missing ignore file.** Copy `~/.config/omacast/file-search.ignore` aside, delete it, `$V call files.refresh '{}'`, wait 2 s. The count is unchanged, `files.list '{"under":"'$HOME'/.config/chromium","limit":0}'` has `matched: 0`, the file is back at mode 0600 with the defaults, and the log has `files: an ignore file is missing; recreating it`. The same holds for `~/.cache/omacast/file-search-untouched.ignore`.
- **Hung rg.** `mkdir ~/omacast-hang && mkfifo ~/omacast-hang/.ignore`, then `$V call files.refresh '{}'`. rg blocks opening the FIFO, `files.list` reports `refreshing: true`, and after 15 s the log has `files: refresh timed out` and `refreshing` is false. `ps -eo pid,ppid,args | grep -E '[r]g |[a]wk |[f]d '` then shows no omacast rg, and once the signal probe's own 15 s pass, no fd either. Free and remove it with `bash -c 'exec 3<>"$1"; : >"$1.new"; mv -f -- "$1.new" "$1"; exec 3>&-' _ ~/omacast-hang/.ignore; rm -rf ~/omacast-hang` right away, because every rg and fd that walks the home dir blocks on it.
- **Toast and accept.** `$V call files.takeToast '{}'` returns the toast with a `files.ignore` action, and a second call returns `null`. `$V call files.ignore '{"path":"'$HOME'/Applications/UnrealEngine"}'` appends `/Applications/UnrealEngine/` to the ignore file, which stays 0600, and a second call returns `added: false`.
- **Argv.** A refresh lasts about 25 ms, too short to catch with `ps`; hold it with the FIFO above (one under `~` and one under `~/.config`). `ps -eo args | grep '[r]g '` then shows only `rg --files [--hidden] --ignore-file ~/.config/omacast/file-search.ignore --ignore-file ~/.cache/omacast/file-search-untouched.ignore <root>` and its parent `timeout -k 2 15 bash -c <constant list script> omacast-files <root> <the two ignore files> [--hidden]`. During a recount it shows `timeout -k 2 60 bash -c <constant script>`, `rg --files <home>`, `awk -F/ -v threshold=5000 <constant program>` and `fd … --exclude node_modules <home>` under `timeout -k 2 15`.
- **Doctor.** `bin/omacast doctor` prints `file search lists … files from <home> and <home>/.config`, the ignore file, and one `left out, large and untouched` line per tree.
- **Push the view.** `$V open`, `$V key ctrl+u`, `$V type "search files"`, `$V key enter`, `$V shot files-empty`. The placeholder reads "Search files…" and "Recent & frequent files" heads the rows. The footer shows "Search Files" once any toast has gone.
- **Path band.** `$V type "oma spec"`, `$V shot files-oma-spec`. The first row is `SPEC.md` with `~/Projects/oma-cast`; on the dev machine a second `SPEC.md` under `~/.config/omarchy/plugins/omamail/docs` follows.
- **Keystroke time.** Type `s`, `p`, `e`, `c` one `$V type` at a time and read `qs log -n -p "$OMARCHY_PATH/shell" -t 40 | grep 'files: ranked'`. On the dev machine (19,917 files, 5 rounds) `s` took 6 to 7 ms and the rest 2 to 3. About 1 in 100 searches lands on a 17 to 38 ms pause of the shell's garbage collector.
- **Open.** `$V key ctrl+u`, `$V type "claude"`, `$V key enter`, `$V shot files-open-hud` within 1.5 s. The OSD names `CLAUDE.md`, the layer is gone, and `$V call frecency.get '{"id":"'$HOME'/Projects/oma-cast/CLAUDE.md"}'` has a score of about 101 and no search terms.
- **Recent.** `$V open`, `$V run builtin:search-files`, `$V shot files-recent`. `CLAUDE.md` is the first row under "Recent & frequent files". `$V key shift+escape` returns to the root with an empty query.
- **Restore.** Put back the saved ignore file and `fileSearch` in `db/settings.json`, and delete the frecency entries the run added for absolute paths.

## Gotchas

- ↵ on a file runs the user's default app for it through `xdg-open`. On the dev machine Markdown opens in Chromium, as a tab in an open window. Open only files the run may show, and leave the window for the user.
- The empty query's rows are computed once per list and signals, 50 ms after the launcher hides or a new list or probe lands. A `files.search` call with another `limit` replaces that cached result, so the view's next empty query recomputes it (about 8 ms).
- Opening a file changes the folder prior: every folder above it gains `ln(1 + opens / 100)`. Undo test opens, or later ranks drift.
- ↵ while the toast shows activates the selected row, not the toast. Accepting the toast is Ctrl+T then ↵, like every toast action in the launcher. The toast leaves the footer after 6 s and does not return for 7 days, because taking it records the ask.
- `files.takeToast` records the ask. Calling it from a test hides the toast from the next real open for 7 days, so restore `fileSearch.askedAt`.
- `qs ipc` drops replies over about 200 KB. `files.list` returns 100 paths by default and at most 1,000 per call.
- rg anchors `--ignore-file` patterns at its working directory. Every run starts in the home dir, and a hand-run check must too (`cd ~`).
- The first recount on a fresh install walks all of `$HOME` (327,662 files on the dev machine) in about 0.75 s, and the first list waits for it.
- A FIFO under the home dir blocks rg, fd and the recount until something opens it for writing or `timeout` ends them, so each hide's refresh waits 15 s on it. Remove the hung-rg test dir as soon as the timeout shows. A plugin reload while one blocks leaves the recount's rg and awk and the signal probe's fd behind, because the shell SIGKILLs `timeout`; freeing the FIFO as the Hung rg step does lets them finish.
